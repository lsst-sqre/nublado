### Bug fixes

- On abnormal Lab startup, fall back to `/tmp` when `$SCRATCH_DIR` is set but the abnormal-startup report cannot be written there, which happens when scratch is really on the same volume as the home directory (as at IDF-dev and -int). If /tmp is also not writeable, the startup initcontainer now fails with `ENOWRITEABLESERVERROOT`.  If this happens, it is likely the lab container will fail to start since it will have no writeable server root, but we try to report an abnormal startup anyway in the faint hope we get far enough to explain the failure to the user.
